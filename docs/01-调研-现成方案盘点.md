# 调研：ESP32 + 显示屏展示 Token Plan 用量 · 现成方案盘点

> 调研日期：2026-11-15 · 结论：**该需求已有成熟的开源生态，无需从零自研**

## 1. TL;DR

- 社区头部项目 [Clawdmeter](https://github.com/HermannBjorgvin/Clawdmeter)（⭐2352 / 418 fork，2026-11-14 仍在更新）已把「ESP32 桌面显示屏看 Claude Code 用量」这件事做成熟，买一块 Waveshare ESP32-S3 AMOLED 板子刷固件即可用。
- 需要**多平台**（Claude Code + Codex + 其他国产 plan）的话，[token-genie](https://github.com/Jensen-JZ/token-genie)（MIT）采用「主机桥接服务 + ESP32 拉取 JSON」的架构，最容易扩展新的数据源（如 GLM Coding Plan）。
- 数据层面，各家都有可编程的用量端点（Claude 有官方 Rate Limits API、OAuth 用量端点和响应头三种路子；智谱 GLM 有 `open.bigmodel.cn/api/monitor/usage/quota/limit`），聚合层写一个 Python 脚本即可。
- 极简路线：Ulanzi TC001 像素钟刷 [AWTRIX 3](https://blueforcer.github.io/awtrix3) 固件，通过 REST API 推自定义内容，**零固件开发**，但只有 32×8 像素点阵，信息量有限。

### 2.1 Clawdmeter（最成熟，只做 Claude Code）

- **硬件**：Waveshare ESP32-S3-Touch-AMOLED-2.16（480×480 彩屏、触摸、可上锂电池），约 $28 / ¥200。
- **数据获取**：主机 daemon（Linux，systemd 用户服务）读 `~/.claude/.credentials.json` 里的 OAuth token，向 `api.anthropic.com/v1/messages` 发一个最小请求（1 个 Haiku token，几乎免费），从**响应头** `anthropic-ratelimit-unified-5h-utilization` / `...-7d-*` 拿利用率，60 秒一轮，经 BLE GATT 推给屏幕。
- **界面**：官方风格 LVGL UI，5h/7d 双仪表 + Clawd 像素动画（用量越高越忙），两侧按钮是 BLE HID 键盘（Space = 语音模式、Shift+Tab = 模式切换），可当 Claude Code 小遥控器。
- **注意**：仓库自带 Anthropic 专有字体和 Clawd 版权素材，作者明确声明未采用 copyleft license，**商用/公开分发需留意**；macOS 支持需自己提 PR。

### 2.2 token-genie（多平台，最易扩展）

- **硬件**：Waveshare ESP32-S3-Touch-AMOLED-1.75（466×466 圆形 AMOLED）。
- **数据获取**：主机上跑纯 stdlib 的 `usage_server.py`（:8787），读 `~/.claude/.credentials.json` 与 `~/.codex/auth.json` 的 OAuth token，调两家官方用量接口，聚合为紧凑 JSON（`claude.five_hour.util` / `codex.seven_day.reset_at` …）。ESP32 **走 WiFi 轮询**（不依赖主机蓝牙，设备可放任意位置），外网访问用 Cloudflare Tunnel / Tailscale / 反代均可。
- **界面**：LVGL 四页（Claude / Codex / 诊断 / WiFi 配网），同心圆弧 + 重置倒计时，**内置中/英/德三语**，MIT 协议。
- **注意**：项目很新、⭐少（6），文档齐全但社区验证少；固件依赖 Waveshare 演示包里 ~340MB 的 vendored 库。

### 2.3 tablo（e-ink 自包含，免服务器）

- TRMNL 7.5" DIY 墨水屏套件（ESP32-S3），固件**直接联网拉数据**，不需要主机桥接；除 Claude/Codex 用量外还有汇率、空气质量等插件。适合想要「断电保留画面、低功耗常开」的墨水屏玩家；7.5" 尺寸大但刷新慢（不适合盯实时变化），套件需从 TRMNL 官方购买。

### 2.4 值得抄的思路（来自小项目）

- `clawdometer-eink`：利用用量接口顺带判断 Claude Code 状态（WORKING / NEEDS-YOU / QUESTION / DONE），**轮到自己时响铃**——对「挂着长任务」场景很实用。
- `ESP32-Token-Display`：一台设备上按按钮轮换显示多个 API Key / 多 provider（OpenRouter 余额、Anthropic RPM/TPM、Claude.ai 5h/7d），配 VSCode 插件免手改配置。

### 2.5 宿主复用路线：Stack-chan 桌面机器人（不买新硬件）

若手头已有 [Stack-chan](https://github.com/m5stack/StackChan)（M5Stack 官方 AI 桌面机器人，⭐1549，2026-11 活跃维护），可以直接把用量显示做成它的新技能：

| 维度 | 官方 StackChan 套件现状 |
| :--- | :--- |
| 主控 | M5Stack CoreS3（ESP32-S3 双核 240MHz、16MB Flash、8MB PSRAM、WiFi+BLE） |
| 显示 | 2.0" 320×240 电容触摸屏（强化玻璃盖板） |
| 表现力 | 1W 喇叭 + 双麦克风、2 个反馈舵机（水平 360° / 俯仰 90°）、12 颗 RGB LED、0.3MP 摄像头 |
| 供电 | 内置 550mAh 电池 + USB-C，天然桌面常驻 |
| 固件 | 原厂固件含 AI Agent / 表情动画 / ESP-NOW 遥控 / 在线应用下载 / OTA，固件源码全开源（repo 含 firmware/app/remote/server 四组件） |
| 二次开发 | 官方 [StackChan-BSP](https://github.com/m5stack/StackChan-BSP)（PlatformIO 库 + 示例），Arduino / UiFlow2 自定义程序是一等公民路径 |
| 先例 | 社区有 ChatGPT / GladOS / MCP-HA 等改造，**未见 token 用量显示先例**（空白点，也是新鲜点） |

**结论**：相比专用的 ESP32 显示屏，复用 Stack-chan 是**零硬件成本**方案，且表现力上限更高（用量告警可以变脸、说话、转头找人），代价是屏幕要和"脸"共用。详见 [02-方案](02-方案-Token用量桌面显示屏.md) 的路线对比。

## 3. 数据源端点汇总（自研/扩展时用）

| 平台 | 获取方式 | 认证 | 备注 |
| :--- | :--- | :--- | :--- |
| **Claude Code 订阅（推荐）** | 向 `/v1/messages` 发最小请求，读响应头 `anthropic-ratelimit-unified-5h/7d-utilization`、`...-reset` | `~/.claude/.credentials.json` 的 OAuth token | Clawdmeter 路线；每次消耗 ~1 Haiku token，基本免费 |
| **Claude Code 订阅（备选）** | `GET api.anthropic.com/api/oauth/usage` | 同上 | 非官方文档端点，返回 `five_hour`/`seven_day` 利用率；已知有激进 429 限流问题（[issue #31021](https://github.com/anthropics/claude-code/issues/31021)） |
| **Claude API / Console** | 官方 [Rate Limits API](https://platform.claude.com/docs/en/api/rate-limits)（2026-04 上线） | API key | 与 Console 显示一致，适合 API 计费账户 |
| **Claude 历史统计** | [ccusage](https://ccusage.com/)（`npx ccusage`） | 无需联网 | 读本地 JSONL 日志，日/周/月/会话用量与成本估算；适合做历史趋势页 |
| **智谱 GLM Coding Plan** | `GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`（国内版） | API key (Bearer) | 官方还提供了 [用量查询插件 glm-plan-usage](https://docs.bigmodel.cn/cn/coding-plan/extension/usage-query-plugin) 可参考其请求格式 |
| **Codex 订阅** | ChatGPT/Codex 官方用量接口（token-genie 的 host 桥有现成实现） | `~/.codex/auth.json` | |
| **OpenRouter** | `GET openrouter.ai/api/v1/credits` | API key | 余额 / 用量 / 上限 |

> 所有「订阅用量」接口都属非公开契约，可能随官方改版失效——聚合层要做版本隔离和降级显示。

## 5. 风险与坑

1. **非官方端点变动**：Claude OAuth 用量端点已出现过持续性 429（见上方 issue），工具链 [claude-pulse 等曾集体失效](https://www.reddit.com/r/ClaudeCode/)。**响应头方案（Clawdmeter 路线）目前最稳**。
2. **凭据安全**：daemon/桥接服务要读 OAuth token 文件，只能本机监听或加 auth key；不要把 token 烧进固件（token-genie 的桥每次刷新时重读磁盘文件，可跟随 CLI 的 token 轮换，值得照抄）。
3. **License**：Clawdmeter 无明确 license 且含 Anthropic 商标资产，仅供自用没问题，**不要拿它公开发布或商用**；token-genie / tablo 是干净的 MIT。
4. **Waveshare 固件构建**：token-genie 需要手动下载 Waveshare 演示包里的 vendored 库（~340MB）并用 pioarduino 平台分支，第一次构建较繁琐。
